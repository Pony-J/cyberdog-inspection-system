## 二、软件架构概览

系统分三层运行:

```
┌─────────────────────────────────────────────────────────────┐
│  运动主机 (Ubuntu 18.04 + ROS2 Foxy)                          │
│  ├── cyberdog_ros2.service   → 运动控制, odom, TF, 状态管理  │
│  └── cyberdog_automation.service → RealSense 相机 + 交互桥接 │
│                                                              │
│  发布: odom, body状态, 相机数据, base TF                      │
│  订阅: body_cmd (速度指令)                                    │
├──────────────────────── DDS (CycloneDDS) ────────────────────┤
│   jetson orin nx(Ubuntu 22.04 + ROS2 Humble)                    │
│  ├── amcl (定位)                                             │
│  ├── Nav2 (路径规划+运动控制)                                  │
│  └── cmd_vel_bridge (Nav2→CyberDog 指令转换)                  │
├──────────────────────── 网络 ───────────────────────┤
│  WSL / 外部电脑                                               │
│  └── RViz2 (可视化, 发送导航目标)                              │
└─────────────────────────────────────────────────────────────┘
```

## 九、Nav2 导航栈配置详解

所有参数文件: `src/cyberdog_nav_bringup/config/nav2_rtabmap_params.yaml`

### 9.1 Planner (全局路径规划)

| 参数 | 值 | 说明 |
|------|-----|------|
| plugin | SmacPlannerHybrid | Hybrid-A*, 支持非全向运动约束 |
| motion_model | DUBIN | 前进+转弯, 无后退 |
| minimum_turning_radius | 0.05 | 近乎原地转弯 |
| max_planning_time | 5.0s | |
| tolerance | 0.35m | 目标容差 |

### 9.2 Controller (局部运动控制)

**使用 MPPI 控制器** (`nav2_mppi_controller::MPPIController`)

| 参数 | 值 | 说明 |
|------|-----|------|
| controller_frequency | **10 Hz** |
| batch_size | 1000 |
| time_steps | 20 | 
| model_dt | 0.1 | 注意控制器频率匹配 |
| iteration_count | 1 |
| motion_model | DiffDrive | 差速驱动 |

9 个 Critics: ConstraintCritic, GoalCritic, GoalAngleCritic, PreferForwardCritic, ObstaclesCritic, CostCritic, PathAlignCritic, PathFollowCritic, PathAngleCritic

### 9.7 Velocity Smoother
```

- `frameid = BODY_FRAME`
- 直接映射 linear_x, linear_y, angular_z

## 十、Behavior Tree (行为树)

### 10.1 navigate_to_pose (主要使用)

文件: `config/behavior_trees/navigate_to_pose_w_replanning_and_recovery.xml`

**设计原则**: Plan-Once + Sequence + 多层 Recovery

```
RecoveryNode(6 retries) "NavigateRecovery"
├── Sequence "NavigateSequence"
│   ├── RecoveryNode(3) "ComputePathToPose"
│   │   ├── ComputePathToPose (planner_id=GridBased)
│   │   └── Recovery: ClearGlobalCostmap → Wait(1s)
│   └── RecoveryNode(3) "FollowPath"
│       ├── FollowPath (controller_id=MPPIController)
│       └── Recovery: ClearLocalCostmap
└── ReactiveFallback "RecoveryFallback"
    ├── GoalUpdated (新目标直接跳过 recovery)
    └── RoundRobin:
        ├── ClearLocalCostmap + ClearGlobalCostmap
        ├── Wait(3s)
        └── BackUp(0.15m, 0.05m/s)
```

### 10.2 navigate_through_poses

文件: `config/behavior_trees/navigate_through_poses_w_replanning_and_recovery.xml`

使用 PipelineSequence + RateController(1Hz) 持续重规划 (因为多路点需要动态更新路径)

### 导出地图
直接从 .db 文件离线导出, 不需要启动任何 ROS 节点:
```bash
# 方法1: Python 直接读 SQLite (推荐, 1秒完成)
python3 scripts/export_map.py                                              # 默认 db + 默认输出
python3 scripts/export_map.py ~/.ros/rtabmap_docker.db                     # 指定 db
python3 scripts/export_map.py ~/.ros/rtabmap_docker.db ./maps/output       # 指定 db + 输出路径

原理: RTAB-Map .db 是 SQLite 数据库, `Admin.opt_map` 字段存储了 zlib 压缩的 2D 栅格 (OccupancyGrid 编码: 0=free, 100=occupied, 255=unknown), 直接解压转换为 PGM 格式即可

将 `.pgm` + `.yaml` 放入 `src/cyberdog_nav_bringup/maps/`, 启动时指定:
```bash
ros2 launch cyberdog_nav_bringup navigation_with_rtabmap_launch.py map_yaml:=/path/to/edited_map.yaml
```
默认路径: `<install>/share/cyberdog_nav_bringup/maps/map.yaml`
